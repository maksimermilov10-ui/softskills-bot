# softskills-bot

Telegram-бот, который помогает студентам пройти тестирование soft skills на платформе «Россия — страна возможностей» ([softskills.rsv.ru](https://softskills.rsv.ru/)): пошаговая инструкция по регистрации и прохождению тестов, быстрый вход для тех, кто уже зарегистрирован, и раздел с анонсами мероприятий.

## Как это устроено

Бот работает в режиме **webhook**, поднят как FastAPI-приложение (не polling) — так он не спит между сообщениями и не тратит лишние ресурсы на постоянный опрос Telegram. Хостится на [Render](https://render.com/): при старте сервис сам регистрирует вебхук по адресу `{PUBLIC_BASE_URL}/telegram-webhook`, дальше Telegram сам присылает туда апдейты.

**Стек:** Python · [python-telegram-bot](https://docs.python-telegram-bot.org/) 21.x · FastAPI · uvicorn/gunicorn · Render (хостинг)

## Структура


## Переменные окружения

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | токен бота, выданный [@BotFather](https://t.me/BotFather) |
| `PUBLIC_BASE_URL` | публичный HTTPS-адрес сервиса без слеша на конце (на Render — `https://<service-name>.onrender.com`); используется, чтобы бот сам поставил себе вебхук |

Локально удобно сложить их в `.env` (см. `.env.example`) и подхватывать любым способом (`export $(cat .env | xargs)`, `python-dotenv` и т. п.) — сам код читает значения через `os.getenv`, без предположений о том, как именно они попали в окружение.

## Запуск локально

```bash
pip install -r requirements.txt
export BOT_TOKEN="токен_от_BotFather"
export PUBLIC_BASE_URL=""   # локально можно оставить пустым — вебхук просто не выставится
uvicorn main:app --reload
```

Без `PUBLIC_BASE_URL` бот поднимется, но Telegram не будет знать, куда слать апдейты — для полноценного локального теста понадобится туннель (например, `ngrok http 8000`) и `PUBLIC_BASE_URL`, указывающий на него.

## Деплой на Render

1. Web Service → подключить этот репозиторий.
2. Build command: `pip install -r requirements.txt`
3. Start command: `gunicorn main:app -k uvicorn.workers.UvicornWorker`
4. В Environment добавить `BOT_TOKEN` и `PUBLIC_BASE_URL` (второй — это уже известный на этот момент адрес самого сервиса на Render).
5. После деплоя бот сам вызовет `setWebhook` при старте — руками ничего дёргать не нужно.

Проверить, что сервис жив: `GET /health` → `{"status": "ok"}`. Полезно повесить внешний пингер (например, UptimeRobot) на этот эндпоинт — на бесплатном тарифе Render сервис засыпает после периода бездействия, и первый апдейт после сна может прийти с задержкой.

## Известные ограничения

- **Прогресс пользователя хранится в памяти процесса** (`context.user_data`), без внешнего хранилища. При перезапуске сервиса (деплой, сон на free-тире) сохранённый шаг инструкции у всех пользователей обнуляется — это не баг, а сознательный компромисс ради простоты на текущем масштабе.
- **Картинки шагов отдаются по прямым ссылкам на Google Drive.** Такие ссылки иногда отдают HTML вместо файла или временно блокируются при частых обращениях — в этом случае `send_guide_step` просто пишет предупреждение в лог и отправляет шаг без картинки. Если это будет происходить регулярно, надёжнее один раз отправить каждое фото через `reply_photo()`, взять `file_id` из ответа Telegram и захардкодить его вместо ссылки на Drive — так файл будет жить на стороне Telegram и не будет зависеть от Google.
